02 / System design

How it works

Client → Payment intent → Capture → Ledger

Correctness boundary

A unique idempotency key identifies a request. Conditional capture and both ledger entries commit in one database transaction.

Path to scale

Scale stateless API instances with pooled PostgreSQL connections. Reconcile provider outcomes through signed, deduplicated webhooks.

Demo scope

Simulated payments only. Provider integration, refunds and reconciliation are roadmap items.
